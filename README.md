# Evals – LLM-as-a-Judge Evaluation & RAG Quality Assessment Platform

An AI evaluation platform designed to assess, compare, and monitor the quality of Large Language Model (LLM) responses using an LLM-as-a-Judge approach.

Evals evaluates AI-generated responses across multiple quality dimensions, helping identify hallucinations, irrelevant answers, context-related issues, and potentially harmful content.

## Overview

As Large Language Models become increasingly popular, evaluating their responses for accuracy, relevance, and safety becomes essential.

**Evals** addresses this challenge by providing a centralized evaluation system that compares model responses and generates explainable quality scores using an independent AI judge.

The platform supports side-by-side model response evaluation, RAG quality assessment, and persistent evaluation history.

## Key Features

- **Multi-Model Comparison:** Compare responses generated by two AI models for the same prompt.
- **LLM-as-a-Judge:** Use an AI judge powered by Llama 3 to evaluate generated responses.
- **Four Evaluation Metrics:** Assess responses using Faithfulness, Relevance, Context Precision, and Toxicity.
- **Explainable Results:** Generate numerical scores and textual explanations for evaluation results.
- **Evaluation History:** Store and retrieve previous evaluation records using PostgreSQL.
- **REST API:** Expose evaluation functionality through FastAPI endpoints.
- **API-Key Authentication:** Protect evaluation endpoints using an API key.
- **Interactive Dashboard:** Visualize evaluation results and historical records through a React interface.
- **Docker Support:** Containerize the backend, frontend, and database services.

## Evaluation Metrics

| Metric | Purpose |
|---|---|
| Faithfulness | Measures whether the response is supported by the provided context. |
| Relevance | Measures how well the response addresses the input question or prompt. |
| Context Precision | Evaluates whether the retrieved context is useful for answering the question. |
| Toxicity | Identifies potentially harmful, offensive, or unsafe content. |

Each metric produces a score between **0 and 1**, along with a textual explanation.

For Toxicity, a higher score indicates a greater toxicity concern. For the other metrics, a higher score generally indicates better quality.

## How It Works

1. The user enters a prompt and provides responses generated by two AI models.
2. The frontend sends the evaluation request to the FastAPI backend.
3. The backend validates the API key and processes the request.
4. The evaluation engine uses an LLM judge to assess response quality.
5. The system generates scores and explanations for the evaluation metrics.
6. Evaluation records are stored in PostgreSQL.
7. The dashboard displays the results and previous evaluation history.

## API Endpoints

Base URL: `/api/v1`

| Method | Endpoint | Description |
|---|---|---|
| GET | `/health` | Check backend health. |
| GET | `/history` | Retrieve recent evaluation records. |
| POST | `/evaluate` | Evaluate and compare two model responses. |
| POST | `/eval/metrics` | Evaluate a test case using RAG quality metrics. |

Protected evaluation requests use the `X-API-Key` request header.

## Environment Configuration

Create a `.env` file in the backend directory using `.env.example` as a reference.

```env
DATABASE_URL=postgresql+asyncpg://postgres:password@db:5432/evals

OLLAMA_BASE_URL=http://host.docker.internal:11434

EVALS_API_KEY=replace_with_a_secure_random_key

OPENAI_API_KEY=
ANTHROPIC_API_KEY=
GEMINI_API_KEY=
```

Use strong, unique credentials for deployment. Never commit actual API keys, database passwords, or other secrets to GitHub.

## Running the Project

### Prerequisites

- Python 3.10+
- Node.js and npm
- Docker and Docker Compose
- PostgreSQL (if running without Docker)
- Ollama with the required model, if using a local Llama 3 deployment

### Run with Docker Compose

From the project root:

```bash
docker compose up --build
```

Access the application:

- Frontend: `http://localhost:3000`
- Backend API: `http://localhost:8000`
- API Documentation: `http://localhost:8000/docs`

### Run the Backend Locally

```bash
cd ai-eval/backend

pip install -r requirements.txt

uvicorn api:app --reload
```

Configure the environment variables and database connection before starting the backend.

## Security Considerations

- Use a strong API key instead of the development default.
- Keep API keys and database credentials outside source control.
- Use HTTPS in production.
- Restrict CORS to trusted frontend origins.
- Do not expose private API keys through frontend environment variables.
- Protect evaluation history and other sensitive endpoints with appropriate authorization.
